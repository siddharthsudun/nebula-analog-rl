SILQ silicon eQualizer · nebula@bits goa · analog track

An RL framework that sizes analog equalizers on real silicon — and checks that what it found is a circuit.

SILQ sizes a PCIe-Gen2 CTLE (continuous-time linear equalizer) on the open SkyWater 130 nm process, talking to ngspice in a closed loop. A reinforcement-learning policy searches the design space for feasible circuits; a constraint-aware numerical stage then closes the requested specification. Every candidate is validated against its own DC operating point before the measurement is allowed to count — and that layer is where the first result is: most designs that pass the published spec sheet turn out not to amplify anything.

The problem

Sizing analog circuits is a slow, expert, one-spec-at-a-time loop.

A designer nudges a transistor width, re-runs SPICE, reads the plots, and repeats — hundreds of times, per spec. The parameter space (every W/L, R, C) is combinatorial, so brute-force sweeps are hopeless. SILQ replaces the human in that loop with a reinforcement-learning policy: the environment is a SPICE testbench of the equalizer, the action is the device sizes, the observation is the measured performance-vs-target gap, and the reward is how close the design is to spec.

Why the spec sheet lets this through

Boost is defined as peak gain minus DC gain. It is a ratio, so a stage that attenuates at DC manufactures boost for free without the peak ever rising. Nothing in the eight checks notices: boost and peak frequency are both computed from that difference, and the other six — HD3, noise, power, area, eye height, eye width — are all easier to satisfy for a stage that passes less signal.

DC gain−5.00 dB  ·  attenuates Peak gain+1.57 dB  ·  barely amplifies, anywhere "Boost"6.56 dB  ·  passes 3–12 dB, peak in band, and the other six

This is a hole in the published spec sheet, not only in our reward — a benchmark that scores a stage which amplifies nothing at any frequency. The measurement is in results/pass_vs_valid.json. The field that closes it, Spec.dc_gain_db_min, adds a DC-gain floor to the spec itself so the hole cannot be exploited, and the guard layer independently rejects the same designs (T4.10) whatever the spec is set to.

What else the guard caught

Three silent failures, each fixed with a regression test.

  • The tail current mirror was in triode. The tail node sat near 0.105 V while the mirror device needs about 0.40 V of Vdsat, so it behaved as a resistor rather than a current source and delivered 16–46% of the requested current — 326 µA of a requested 1000 µA. Tail current was a compressed non-linear knob, and the mirror provided none of the PVT behaviour it was added for. Fixed by moving the input common mode and by setting the mirror length from a measured accuracy sweep (34.0% worst-case error at 0.5 µm, 3.7% at 2 µm). The check threshold was not touched; the circuit was changed to meet it.
  • The guard's own probe was reading a different design. The .op probe runs against whatever the resident simulator currently holds, and the evaluator never primed it with the candidate — so Tier 2 compared one design's operating point against another design's requested values. The same design evaluated twice in a row changed verdict on 9 of 14 attempts. Nothing had asserted that identical input gives identical output, which is the property that makes every other check mean anything. It is now asserted five ways.
  • Widths above 100 µm were silently unbuildable. sky130_fd_pr__nfet_01v8 solves at W = 100 µm and aborts at 101 with could not find a valid modelname. The old code clamped at 200 µm, and on the resident-simulator path that abort carries no exit code — so it read as a clean run that happened to produce no numbers. Width is now drawn as parallel fingers, which is what real layout does anyway.
The search space

20.4% of the declared action space is a buildable circuit.

Sampling the action space uniformly — no agent, no trajectory — and running every sample through the guard layer gives 51 valid designs out of 250. Conditioned on tail current, the picture is a band rather than a slope: there is a workable region up to about 1 mA, and nothing valid in 90 samples above it. We measured out to 20 mA, found nothing buildable above roughly 1 mA, and capped the declared tail-current range there.

valid designs per 30 uniform samples
From results/itail_profile.json. Higher is better. Every other parameter is sampled uniformly at each point.

The mechanism is headroom: more tail current means more Vgs on the input pair, which pulls the tail node down, which is exactly the headroom the mirror needs. Current and mirror headroom trade against each other one-for-one, and past a few hundred µA the mirror loses. The tail-current cap is the one range we narrowed, and it is on measured physics rather than to flatter a result: above 1 mA nothing is valid across 90 samples, and the cap is recorded in the commit history. Every other range is untouched.

Robustness

The delivered circuit passes all 45 PVT corners.

The grid is the full one: 5 process corners (TT/SS/FF/SF/FS) × 3 voltages (VDD ±5%) × 3 temperatures (0/27/125 °C), with HD3 and input-referred noise simulated at every corner — no fast approximations. The instrument is stricter than the one behind every other number on this page: each corner goes through the full guard layer, and each is scored against the circuit's own requested target with the ±1.5 dB tolerance switched on, which adds a tenth check that the other results do not carry. Everything is in results/delivered_circuit.json.

The candidate was not hand-picked. All 22 designs that met the strict criterion on the held-out spec set were swept over all 45 corners under a rule written before any corner was simulated; one of the 22 came back clean, and that is the one below. The two dominant failure modes across the rest were DC gain and saturation headroom, concentrated at low supply and high temperature.

The requested target was 8.920 dB of boost over a 14.83 dB channel, and the worst corner of the 45 lands 1.081 dB from it — inside the tolerance everywhere, not only at nominal. DC gain is the binding constraint, with 1.04 dB of headroom above the floor at ss/1.89 V/125 °C; everything else clears by more than an order of magnitude. Area is marked non-binding for a stronger reason than a sample: every term of the area model increases with its own variable, so the upper corner of the action space is a true analytic supremum — 0.002227 mm² against a 0.05 mm² budget, a 22× margin — and the constraint cannot fail anywhere in the space, not merely in the runs we did. What this is not: the optimisation itself ran at TT only — nothing in SILQ was trained or scored at corners — so this is an out-of-distribution measurement of one generated candidate, not a claim that the framework produces PVT-robust designs in general. One in twenty-two did.

The artifact

A real, sized circuit — not a block diagram.

This is the design the PVT sweep above characterizes: a 1-stage source-degenerated CTLE built from SKY130 nfet_01v8 devices, exported as a netlist that runs in ngspice as-is. How the peaking works

The Rs·Cs across the differential-pair sources creates a zero that boosts the high-frequency (Nyquist) band and flattens the channel loss. The sizing problem is to place that zero inside the 1.25–2.5 GHz window while holding linearity, noise, power and area, trading W/L against tail current, Rs, Cs and the load. Those six numbers are the action space the policy searches.

Why it's fast enough to be real

A resident simulator makes training on real SPICE affordable.

Loading the SKY130 corner models costs about 15 seconds every time ngspice launches. SILQ keeps the simulator resident and re-evaluates each candidate with alterparam; reset, so the models parse once. Measured over 10 evaluations each (results/speedup.json): 77.5 ms per AC evaluation resident, against 6370.5 ms for a fresh subprocess — 82.2×. An earlier figure of 350× compared one evaluation against a whole process launch plus model reparse, which is not the quantity that matters during a search.

  • Real, not behavioral. Every number is measured on SKY130 BSIM transistors in ngspice — AC peaking, HD3 by transient + FFT, input-referred noise by .noise, supply power from the actual rail current.
  • Honest baselines. A first, naïve RL setup lost to Bayesian search; we reformulated to a sequential design-closing MDP — and kept the losing result in the git history rather than deleting it.
  • What the learning does, stated as a limit. The frozen PPO policy (results/seq_clean40k.zip) is a strong feasibility solver: it reaches a valid circuit in a median of 4 evaluations, against the 2,394 the poster's full parameter sweep needs to find its first. What it does not do on its own is hit a requested boost above a matched-chance null — that is the constrained refinement stage's job, and keeping the two separate is the point. The policy supplies feasibility; the refinement supplies precision. This is reported as the boundary of the RL claim, not hidden behind it.
  • Two metrics used to be constants. The environment defaulted to fast=True, which skips the transient-HD3 and .noise analyses and substitutes −40 dB and 1.0 mV. Every training run and every search number this project published earlier scored those two as constants. fast=False is now the default; the PVT characterizations always ran that way.
Stack & reproducibility

Open tools, top to bottom.

Python · PPO (stable-baselines3) · Gymnasium · ngspice via libngspice · SkyWater SKY130 open PDK · Optuna and CMA-ES (baselines). The repository holds the circuit generator, the resident-simulator server, the RL environment, the guard layer, the baselines, the PVT engine and the characterization. Every number on this page is written to an artifact in results/ by the script that measured it, and each of these runs with no arguments:

python -m silq.experiments.pass_vs_valid python -m silq.experiments.space_validity python -m silq.experiments.itail_profile python -m silq.experiments.speedup python -m silq.experiments.pvt_signoff --report-only

Scope notes for review. The CTLE sizing, the AC / HD3 / noise / power / area measurements, the eye (channel + CTLE + adapted 1-tap DFE) and the 45-corner PVT sweep are simulated on SKY130. The channel is a minimum-phase PCIe-Gen2 model, at the loss each spec asks for — 14.83 dB at Nyquist for the delivered circuit; the eye is Monte-Carlo over a random NRZ pattern. Boost is treated as the poster's 3–12 dB tunable range for pass/fail everywhere on this page except the delivered circuit, which is additionally scored against its requested target with a ±1.5 dB tolerance. The baselines are random search, Bayesian optimization (Optuna TPE) and CMA-ES — there is no grid baseline. Area is measured but cannot fail against the 0.05 mm² budget. The natural-language front-end parses a plain-English request into the framework's Spec object, with a keyword fallback when no API key is present. Two things the delivered circuit does not establish: the policy alone does not demonstrate target-conditioned design — closing the target is the refinement stage's job — and strict solve counts over the held-out spec set do not clear their matched chance null, so they are not claimed here.

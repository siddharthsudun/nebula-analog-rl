# silQ frontend: graphite and electric cyan

The frontend now uses the user-selected graphite and cyan direction with the existing silQ wordmark, typography and linked Astera Labs assets. The studio retains the circuit, sizing, constraints, design controls, exports and verification results. Backend algorithms and training are outside this change.

## Product layout

- Studio: signal-to-silicon introduction, design brief, optional SNR under Advanced, numeric constraints and the circuit workspace.
- Evidence: historical Auto, Fastest and Thinking comparisons, with legacy strategies and source records in an expandable method section.
- Explore: guard sandbox, archived results, benchmark instruments and SNR experiments.

The moving wave background is removed from the active page. A restrained static chip illustration identifies the receive path as a concept view. A new five-second silent Higgsfield film uses graphite silicon and a cyan differential trace. The exact wordmark and Astera logo are HTML overlays, not generated lettering. The intro supports skip, Escape, focus containment and return, session-only automatic playback, replay and reduced-motion bypass. It is hidden until JavaScript starts it, and autoplay failure has a bounded fallback.

## Original UI backup

`backups/frontend-original-2026-09-10.zip` and the corresponding directory preserve the original yellow UI, original intro and hero videos, Astera logos, vendored animation scripts and optional SNR companion script. Original HTML, styles, app and charts were copied from the snapshot made before redesign edits. The directory contains `RESTORE.md` and a SHA-256 manifest for all 12 files. Backup verification checked both the manifest and equality with the pre-edit snapshot.

To restore, save the current dashboard elsewhere, then copy the backup's `dashboard` contents over the project `dashboard` directory. No backend changes are needed. New unused assets can remain; the original HTML does not reference them. Hard-refresh the browser afterward.

## Evidence provenance

`dashboard/static/data/mode-evidence.json` is a static snapshot generated by `work/frontend-overhaul/build_evidence.py`, using `dashboard/static/data/mode_bench5.json`, its harness and `results/target_tracking_clean40k.json`. Copies and hashes of the source records are available from the Evidence view.

The historical benchmark contains 31 matched cases of 32 planned, spec seed 137, at nominal TT, before automatic PVT repair and optional SNR assessment. These are search modes, not independently trained models. Auto and Thinking solved 30/31; Fastest solved 24/31. Boost-error medians have explicit measured-case denominators; Fastest has seven unmeasured cases. Non-solve rate is not BER. Historical error and runtime do not establish performance of the current integrated pipeline.

The expandable table includes an empirical target-hit reference matched to each case's optimizer evaluation budget. It does not check physical constraints and is not an equivalent full solve baseline or proof of infeasibility.
